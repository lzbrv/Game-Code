## 1. What changed, by area

This is written as "what a player or a developer would notice", not as a file list. The file list is
`git status`, and it is 1,637 paths long.

### 1.1 Characters — the biggest visible change

**Before:** every one of the ten characters rendered as Epic's default Mannequin with a team tint.
The character-select screen described ten distinct fighters and the arena showed you ten identical
grey mannequins in two colours.

**Now:** each character has its **own body mesh**, built from a per-character recipe, with its own
proportions, silhouette details and accent colour. All ten bind to **one shared skeleton**, so one
retargeted animation set drives all of them — which is why adding a body costs about 640 KB rather
than a new animation pipeline each time. Each also has a **rendered portrait** on the select screen.

**What you will notice:** you can tell most of them apart now, both on the card and in the world.
Eight of the ten separate cleanly at the design's own 3,000 uu "who is that" distance; **Rocco and
Elle do not**, and that is one of your decisions (§4.3).

**The honest caveat:** this art is *generated low-poly geometry*, not modelled characters. Compared
to the smooth Mannequin it replaced it is cruder — axis-aligned boxes rather than anatomy. It is a
big step forward for **identity** and a step sideways at best for **fidelity**. And the old smooth
body is still in the build: the practice-range dummies are Mannequins, so two body styles are on
screen in the same session. That is deliberate in mechanism and unintended in effect
(`docs/KNOWN_LIMITATIONS.md` item 33).

### 1.2 Sound — from a handful of files to a real bank

**Before:** 28 WAVs and a thin set of trigger points.

**Now:** a **71-event sound bank**, generated by a deterministic synthesiser in the repo
(`Scripts/generate_sounds.py`), imported into a data-asset bank, and wired to real triggers across
combat, movement, abilities, UI and music. Footsteps, weapon fire per weapon, hit and headshot
confirmations, kill, parry, dash, wall-jump, Core pickup/turnover/goal, per-character ability cues,
button presses, countdown, a title bed and match ambience with victory/defeat stingers.

**What you will notice:** the game has an audio identity where it previously had event beeps. The
post-match results screen no longer sits in 11–14 seconds of silence. A full mix pass set relative
levels rather than leaving everything at 1.0.

### 1.3 The arena and its lighting

**Before:** a procedurally built arena, flatly lit, with two red engine-error lines burned into
every screenshot.

**Now:** the arena ships as **`/Game/Maps/Arena_Baked`** — a real, editable level of 647 placed,
individually named actors with One File Per Actor, so several people can edit it at once without
fighting over one `.umap`. The lighting was rebuilt (key/rim/atmosphere with explicit priorities), a
skyline and beacons added, the neon materials gained a pulse, the floor grid and cove were reworked,
and the collaborator's hand-built centre kit was adopted and themed rather than bulldozed.

**What you will notice:** it is considerably darker and much more saturated — mean luminance on
matched framings went 61.1 → 45.7 and the effectively-black area 50.5% → 65.3%. Looked at rather
than measured, that trade paid off: the deep blues and the amber goal read far better than the hazy
original. But **it is a dark shooter now**, and the blocky bodies are already hard to pick out; if
you want it brighter, that is a knob, not a rebuild.

**What you will also notice:** above the wall line there is *nothing*. The sky band measures a flat
black field (luma mean 3.45, 99th percentile 5.0). Every wide or upward shot ends in void. It is the
cheapest remaining improvement on the whole list.

### 1.4 Menus, HUD and character select

**Before:** a Canvas-drawn UI with placeholder art, a magenta crosshair, a hung-looking practice
clock reading `20159:53`, and a translucent HUD you could read the world through.

**Now:** the title screen draws the artist's real sprite art through a UMG renderer (39 of 39 art
slots resolve to a texture, not a white box); the character-select screen carries all ten portraits;
there is a working options tree with rebindable controls, an audio page, a crosshair page and a call
sign; the HUD score panel is opaque; the kill feed has vector glyphs; the practice range says
`PRACTICE` instead of a fortnight-long half; and text is drawn from bitmap glyph atlases with a
Latin-1 fallback sheet so accented names render.

**What you will notice on your own laptop:** the select-card label **"ACTIVATED" clips to
"ACTIVAT"** on any 16:10 display, and reads correctly at 1920×1080. That is why it survived — the
monitor a developer tests on is 16:9. `docs/KNOWN_LIMITATIONS.md` item 39.

### 1.6 Under the hood, with no player-visible effect

Worth knowing because it is most of the diff and none of the risk:

* **Anti-cheat surface.** 674 console commands were audited one by one. 446 are now compiled out of
  Shipping entirely, 163 ship inert behind the engine's cheat flag. The commands that grant the Core
  or override the roster are **physically absent** from the Shipping binary — verified by symbol
  scan on the linked artefact, not by reading source. 20 remain that should be flagged and are not
  (item 36).
* **Structural refactor.** Several very large files were split — the character, the Core and the
  arena builder each became a family of files — with no replicated property, RPC, damage number or
  tuning value changed. Pure relocation, gated.
* **Config hygiene.** Windows-only renderer settings that a collaborator's editor kept re-appending
  were removed, and a pre-commit hook (`Scripts/setup-hooks.sh`) now catches them coming back.
* **Documentation.** `README.md` was rewritten and re-checked against the tree; `docs/` gained
  `KNOWN_LIMITATIONS.md`; the Git/LFS, setup and editor docs were re-measured.

## 2. What is verified, and how

Every claim in this section is backed by a log or a frame in the release report bundle. Nothing here
is "we think it works".

### 2.1 It builds, from clean, in both configurations

Both targets were built from a genuine `--clean` (not an incremental no-op — the `.o` timestamps
were checked, because the first attempt printed `Result: Succeeded` in 10 seconds and proved
nothing):

* `Trace` / **Shipping** — one literal `Result: Succeeded`, 95 of 95 object files rebuilt.
* `TraceEditor` / **Development** — one literal `Result: Succeeded`, 95 of 95 object files rebuilt.

Both were then rebuilt and re-verified a second time, eleven hours later, on the day's final tree.
Identical results.

### 2.2 It runs, extensively, headless

Roughly 50 headless runs across nine lanes on the final binaries, plus hundreds more during the
implementation waves. What that covers:

* **A command-level acceptance battery** — 46 items pass. Match flow, half-time and the side switch,
  goal sides, arena performance, movement audit, bounds, abilities, ammo, the Core rules, the
  practice range's cheat isolation (three runs: red arm, green arm, then the range itself), audio
  loudness and event coverage, FX bursts, the carrier trail, and the UI verifiers on both renderers.
* **The character census, ten times over** — every pawn drawn in its own body, its own materials and
  its own animation class, with red arms that were *seen to fail* before the green ones were
  trusted.
* **Two-process client/server runs** on private ports for anything involving prediction, including
  eight surf rides at 40 ms of emulated latency with **zero prediction corrections**.
* **A screenshot battery** at eight fixed cameras that are byte-identical to the pre-overhaul
  baseline set, so the before/after pairs are the same scene rather than two different ones.

### 2.3 The frames are clean

Every pre-overhaul frame carried two lines of red engine error burned into the image. Measured by
exact colour match on the engine's own warning red and amber: every baseline frame carries 226 px of
red and 496 px of amber; **889 of 889** post-overhaul frames on disk carry **zero**.

### 2.4 The method, so you can judge the evidence

Three rules were applied throughout and are worth knowing when you read any of the reports:

* **A green harness that cannot go red proves nothing.** Almost every check here has a "red arm"
  that switches the rule off, and the red arm was run first and seen to fail.
* **A build is not proof.** Object-file timestamps were checked against source timestamps, because a
  green build can be an incremental no-op.
* **A frame is not proof until its camera is confirmed.** Every screenshot's own logged camera
  position was validated before the frame was read.

## 3. What is NOT verified, and needs a human to look at it

Be blunt about this: the following are the parts a person has to eyeball, because no automated check
covers them.

### 3.1 The packaged game has never run — this is the big one

"Both configs green" has always meant "the Shipping target compiles and links". Nobody in seven
waves ran the artefact. We ran it on the last day:

* The bare Shipping binary **aborts at launch** — `dyld: Library not loaded:
  @rpath/libmetalirconverter.dylib`, SIGABRT, confirmed by macOS's own crash report. The library
  exists; the binary's search path has three directory levels too many for where the binary actually
  sits. It is correct from inside a `.app` bundle and wrong for the bare binary, on this install
  layout (engine under `/Users/Shared`, project under `/Users/<user>`).
* The `.app` copy clears that and **exits 1 with no output**, because a Shipping game build compiles
  its logging out — and because **there is no cooked content anywhere in the project**.

Neither is a regression this work caused, and neither means the code is wrong: a UE game target
legitimately needs cooked content. What it means is that **the packaged path is wholly unexercised**.
The supported path — the editor plus `Scripts/run-listen-server.sh` — is exercised heavily and works.
If you ever want a distributable build, budget real time for cook + package; it has never been tried.

### 3.2 Windows

Everything above was measured on macOS. The Windows build is unverified for this pass. macOS
structurally cannot catch the MSVC variable-shadowing errors that have broken this project's build
before — there are now checker scripts for the known classes (`Scripts/check-*.py`, all clean), but a
real Windows build is the only real gate. **Ask a colleague on Windows to build before anyone else
pulls.**

### 3.3 Things that need eyes, not a test

* **Does the arena read well at its new darkness?** The numbers say it got much darker and the
  judgement says it got much better. That is a judgement. Play it.
* **Can you tell the ten characters apart in a fight?** Eight pass a still-frame test at 3,000 uu.
  Nobody has played a real match and reported whether that translates.
* **Does the practice range's style clash bother you?** Blocky players, smooth mannequin targets.
* **The mix.** Levels were set by measurement (loudness per family) and checked by ear only in
  headless captures. Nobody has played a full match with sound on and said "the footsteps are right".
* **Character-select navigation by hand.** The mouse pointer beats the keyboard on that screen
  (item 26), which means scripted select-screen captures are not trustworthy. Click through it once
  yourself.
* **Bot competence.** Bots play the full ruleset and *can* score by throwing. Whether they defend
  well, or score often enough to be a useful practice partner, is unmeasured and is a design
  question.

### 3.4 Coverage gaps we know about and did not close

* **Surf under packet loss, tick-rate mismatch, while carrying the Core, or combined with dash or
  parry.** The prediction evidence is eight rides at 40 ms of clean latency. Read "zero corrections"
  as scoped to exactly that (item 32).
* **The remote-character claim has never been falsified.** All ten characters demonstrably render
  correctly on remote clients — but the red arm that would prove that check is *capable* of failing
  has only ever bitten locally-owned pawns, never a truly remote one (item 43). The wiring was
  separately confirmed at asset level; the falsifiability was not.

## 4. Decisions waiting for you

Five. None of them can be made by anyone else, and each is stated with what it costs either way.

### 4.1 Mode B: the throw-speed change broke a bot acceptance test

Patch 28 §4 cut the Core throw speed from 3300 to 2900 uu/s, exactly as you asked. Step 5 of the
mode-B verification suite — "a bot scores by throwing at the goal" — now fails, and it is the throw
speed that does it. That was proved by an A/B on **one binary**: shipped 2900 fails twice, the same
binary forced back to 3300 passes twice, and the two historical runs of the suite from before the
change also pass.

The arithmetic is deterministic: the test's scripted shot needs **5,354 uu** of reach and the Core
now carries **4,997 uu**. Out of range by 357 uu. At 3300 it had 6,728 uu. Closing the distance does
not rescue it — approaching head-on, the shot becomes legal only 201 uu before the bot commits to
carrying it in, which is about 0.2 s and inside the bot's own reaction delay.

**Your three options:**

1. **Accept it.** A slower Core means bots shoot from closer, and the test's 4,800 uu standoff is
   simply the wrong test now. Moving the standoff is one constant. *Cost: none, but you are choosing
   to say the bots' shooting range is meant to be shorter.*
2. **Lower the bots' carry-in commit distance** (currently 4,200 uu) so the throw window reopens.
   *Cost: this is a real change to how bots play, not a test fix. They will commit to running it in
   later, and shoot more.*
3. **Retune mode B.** Range goes as the square of speed, so a 12.1% speed cut is a 22.8% range cut —
   and the goal has been 2,400 uu further out and 1,100 uu higher since spec v6. *Cost: a tuning
   pass, with everything that touches.*

**What is not an option:** lowering the shot-quality gate. At that standoff the shot is not near the
ragged edge of range, it is past the end of it. A gate of zero would still refuse it.

### 4.2 Surf: re-bake the arena, or ship the mechanic unreachable?

Surf works. It is predicted, bounded, measured and has zero prediction corrections at 40 ms. It is
also **unreachable by a player**, because the four rails are built by the arena builder and the
shipping map is a *baked* level that builds nothing. PLAY and PRACTICE both load the baked map. Start
Trace normally and there is nothing to surf.

**To try it today:** `Scripts/run-listen-server.sh --map /Game/Maps/Arena`.

**To ship it:** somebody has to re-bake `Arena_Baked`. **Know the cost before you say yes.** The last
preserving re-bake **lost nine hand-placed top-centre-tower pieces** contributed by a collaborator,
because the editor's duplicate-actor API cannot work in a headless commandlet. They were recovered
and re-created by a different route, and the recovery is verified — the census holds all 18 cluster
pieces paired one-to-one by mirror, and a collision probe reads 705.2 uu against its untouched mirror
control's number to a tenth of a unit. **Nothing is currently lost.** But a re-bake rewrites all 647
actor packages, it is the operation that lost them once, and five further hand-copied centre floor
lamps are carried through by hand (§4.4).

**Your options:** re-bake and ship surf; ship without it and say so in the release notes (the README
and the limitations list already say so); or hand-place four rails in the editor, which avoids the
re-bake entirely and is probably the cheapest safe answer.

### 4.3 Rocco and Elle do not read at 3,000 uu

Eight of the ten characters are identifiable at the design's own "who is that" distance. Two are not,
and both are blocked by their own design sheets rather than by execution:

* **Rocco** — his sheet freezes his chassis verbatim and freezes his crest at 6 uu thick against a
  ceiling of 8. There is nothing left that is *legal* to widen.
* **Elle** — her identity is defined as "silhouette only" and her accent lives on her half-cape, so
  seen from the front she has no crown ornament at all.

**Each is one decision away:** bless a sheet deviation on Rocco's crest, or decide Elle is allowed a
crown break. Either is a small implementation job once decided. Doing nothing ships two characters
you cannot name at range.

### 4.4 The five hand-copied centre floor lamps

Five floor lamps in the centre of the arena (`Floor_Lamp_3/4/6/7/8`) were hand-copied by a
collaborator and have been carried through every bake since. They were found early and deliberately
**not** deleted, because deleting another person's hand edit is not a decision an automated pass
should make.

**Your call:** keep them (they are harmless, and they are somebody's work), or remove them for a
clean census. Related to §4.2 — if you re-bake, decide this first, because a re-bake is when they
would go.

### 4.5 Font licensing — unresolved, and unchanged by this work

**Nothing here has been weakened, and nothing here is settled.**

* The licensed font **files** (Sofachrome, Erbaum) are **not** in the repository and must never be
  committed. They are gitignored, with an exception only for SIL-OFL Lato.
* The **baked glyph atlases** — textures of every glyph, plus metrics — **are** committed, and they
  are what the game draws.
* Sofachrome ships under Typodermic's free **desktop** licence, which explicitly allows
  "app (not embedded)" and explicitly forbids "app (embedded)". Rendering the face to an image with a
  licensed desktop installation and shipping the image is the "not embedded" case, and it is the same
  route the artist's existing sprite sheet took.
* **The honest caveat, restated because it matters:** a *full-alphabet* atlas is a greyer position
  than pre-rendering a fixed list of words, because it is enough to set arbitrary text — arguably the
  capability the "not embedded" clause exists to withhold. This was raised with you and you chose the
  atlas deliberately for the consistency it buys.

**The exposure is that this repository is public.** If Trace is ever distributed commercially, or the
position needs to be defensible rather than arguable, the fix is to **buy Typodermic's app licence**
for Sofachrome (they sell one) and then embed the real font — which is one constant in
`TraceMenuArtStyle`, deliberately, so that the licensing decision is one line of code rather than a
rewrite. Typography is frozen until you decide. Full detail: `docs/FONTS.md`.

## 5. How this was committed, and how to revert it

### 5.1 What exists now

* **Branch `release/overhaul-2026-08`**, pushed to `origin`. This is the overhaul.
* **`main` is untouched**, still at `36401e2` "Rocco wears his own model, and it moves". Anyone who
  does not check out the branch is unaffected.
* **Tag `pre-overhaul-2026-08`**, pushed, pointing at that same `36401e2` — a named restore point
  that does not depend on remembering a hash.

To get the work:

```sh
git fetch origin
git checkout release/overhaul-2026-08
git lfs pull                 # 968 LFS objects, ~56 MB
Scripts/build.sh             # expect: Result: Succeeded
```

They are ordered so the history reads as tooling -> code -> content -> docs. Each message explains
the *effects* of its change, not just its files.

### 5.3 How to revert

**Cheapest and safest: do not merge.** `main` already is the pre-overhaul state. If the branch turns
out to be wrong, delete it — nothing else is affected.

If it has already been merged and you want out:

```sh
git revert -m 1 <merge-commit>          # undo the whole thing
```

To drop one piece rather than all of it, revert that commit alone — for example
`git revert 31ca5ec` removes the map work and keeps the characters, sound and code. Be aware the
commits are ordered but not fully independent: reverting the code commit while keeping the content
commits leaves assets nothing loads, which is inert but untidy. The clean units are "all of it" or
"one content area".

To go back to the exact pre-overhaul tree at any time:

```sh
git checkout pre-overhaul-2026-08
```

### 5.4 One deliberate non-deletion

`Content/ramp.uasset` — an unreferenced stray at the content root, imported from a collaborator's
machine — was **left in place**. It is provably referenced by nothing (verified by a sweep of all
1,667 packages) and is safe to delete, but removing another person's file was not a call to make
without you. Same reasoning kept the Fish test maps and the five hand-copied centre floor lamps.
